## 1. Общее описание
Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании. Система состоит из клиентского мобильного приложения и серверной части.

## 2. Клиентская часть (Android-приложение)
Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java** с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий функционал:

*   **Регистрация и авторизация** сотрудника.
*   **Настройка личного профиля**.
*   **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны иметь возможность дать бинарный ответ (**принял** / **не принял**).
*   **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности посещения.
*   **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## 3. Серверная часть
Сервер представляет собой **микросервис на Spring Boot**, работающий с СУБД **PostgreSQL** или **H2**.

Серверное приложение должно:
*   Предоставлять API, необходимый для полноценной работы мобильного приложения.
*   Осуществлять все основные операции с данными в базе через **Spring Data JPA**.
*   Использовать **Liquibase** для создания схемы базы данных и ее предзаполнения.


## User Stories

### US-1. Регистрация и авторизация

Как сотрудник, я хочу зарегистрироваться и авторизоваться в приложении, чтобы получить доступ к функциям планирования встреч и управлению профилем.

### US-2. Управление личным профилем

Как сотрудник, я хочу просматривать и редактировать свой профиль, чтобы мои данные были актуальными и корректными.

### US-3. Создание встречи

Как сотрудник, я хочу создавать встречи с приглашением других сотрудников, чтобы организовывать рабочие обсуждения.

### US-4. Управление приглашениями

Как сотрудник, я хочу видеть список приглашений и отвечать на них (принять/отклонить), чтобы управлять своим участием во встречах.

### US-5. Просмотр расписания

Как сотрудник, я хочу видеть своё расписание по дням, неделям и месяцам, чтобы эффективно планировать рабочее время.


## Use Cases

### US-1: Регистрация и авторизация

#### UC-1.1 Регистрация пользователя

**Предусловия:** Пользователь не авторизован, имеет доступ к приложению.  
**Основной сценарий:**
1. Пользователь открывает экран регистрации
2. Вводит email, пароль, ФИО
3. Нажимает «Зарегистрироваться»
4. Система валидирует данные и создаёт аккаунт
5. Пользователь перенаправляется на экран входа

**Альтернативный сценарий:** Если email уже существует, система показывает ошибку и предлагает войти.  
**Постусловия:** Аккаунт создан, пользователь может авторизоваться.

#### UC-1.2 Авторизация пользователя

**Предусловия:** пользователь зарегистрирован
**Основной сценарий:**

1. Пользователь открывает экран входа.  
2. Пользователь вводит email и пароль
3. Нажимает «Войти»
4. Система проверяет данные и выдаёт токен
5. Открывается главный экран

**Альтернативный сценарий:** Если данные некорректны, показывает ошибку.  
**Постусловия:** пользователь авторизован

### US-2: Настройка личного профиля

**Предусловия:** Пользователь авторизован.  
**Основной сценарий:**  
1. Пользователь переходит в раздел "Профиль".  
2. Редактирует данные (имя, фото, контакты).  
3. Нажимает "Сохранить".  
4. Система обновляет данные в БД.  
**Альтернативный сценарий:** Если данные некорректны, показывает ошибку.  
**Постусловия:** Профиль обновлен и виден другим пользователям.

### US-3: Создание новой встречи

**Предусловия:** Пользователь авторизован.  
**Основной сценарий:**  
1. Пользователь переходит в раздел "Создать встречу".  
2. Выбирает дату, часовой слот (строго по часам, напр. 9:00-10:00).  
3. Добавляет описание, приглашает сотрудников (поиск по имени/email).  
4. Нажимает "Создать".  
5. Система сохраняет встречу и отправляет приглашения.  
**Альтернативный сценарий:** Если слот занят, предлагает альтернативу.  
**Постусловия:** Встреча создана, приглашения разосланы.

### US-4: Просмотр списка активных приглашений

**Предусловия:** Пользователь авторизован.  
**Основной сценарий:**  
1. Пользователь переходит в раздел "Приглашения".  
2. Видит список активных приглашений с деталями (дата, время, организатор).  
3. Для каждого выбирает "Принять" или "Отклонить".  
**Альтернативный сценарий:** Если нет приглашений, показывает сообщение.  
**Постусловия:** Статус приглашения обновлен.

### US-5: Просмотр собственного расписания встреч

**Предусловия:** Пользователь авторизован.  
**Основной сценарий:**  
1. Пользователь переходит в раздел "Расписание".  
2. Выбирает вид: день, неделя, месяц.  
3. Система отображает встречи в выбранном разрезе.  
**Альтернативный сценарий:** Если нет встреч, показывает пустой календарь.  
**Постусловия:** Пользователь видит актуальное расписание.


## Набор задач для backend-разработчика

### BE-1: Настроить проект и БД
   Создать Spring Boot проект с зависимостями (Spring Data JPA, Liquibase). Настроить PostgreSQL/H2. Создать схему БД с таблицами: Users, Profiles, Meetings, Invitations. Предзаполнить тестовыми данными через Liquibase.

### BE-2: Реализовать API для регистрации и авторизации
   Создать эндпоинты: POST /register, POST /login. Использовать JWT или сессии для аутентификации. Интегрировать с JPA для хранения пользователей.

### BE-3: API для профиля 
   Эндпоинты: GET /profile/{id}, PUT /profile/{id}. Обновление данных профиля через JPA.

### BE-4: API для создания встреч
   POST /meetings: Создать встречу с слотами по часам. Проверка на конфликты. Отправка приглашений (сохранить в Invitations).

### BE-5: API для приглашений
   GET /invitations (список для пользователя), PUT /invitations/{id}/respond (принять/отклонить).

### BE-6: API для расписания
   GET /schedule?view=day/week/month&date=... Возврат списка встреч для пользователя.

### BE-7: Тестирование и документация
   Написать unit-тесты для сервисов. Документировать API (Swagger).

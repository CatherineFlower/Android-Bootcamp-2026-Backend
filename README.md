# Техническое задание на разработку программного продукта для планирования встреч

## 1. Общие описание
Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании. Система состоит из клиентского мобильного приложения и серверной части.

## 2. Клиентская часть (Android-приложение)
Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java** с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий функционал:

*   **Регистрация и авторизация** сотрудника.
*   **Настройка личного профиля**.
*   **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны иметь возможность дать бинарный ответ (**принял** / **не принял**).
*   **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности посещения.
*   **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## 3. Серверная часть
Сервер представляет собой **микросервис на Spring Boot**, работающий с СУБД **PostgreSQL** или **H2**.

Серверное приложение должно:
*   Предоставлять API, необходимый для полноценной работы мобильного приложения.
*   Осуществлять все основные операции с данными в базе через **Spring Data JPA**.
*   Использовать **Liquibase** для создания схемы базы данных и ее предзаполнения.

User Stories

Как сотрудник, я хочу зарегистрироваться и войти в систему, чтобы получить доступ к своему рабочему расписанию.

Как сотрудник, я хочу редактировать свой профиль, чтобы мои коллеги могли видеть актуальную информацию обо мне.

Как сотрудник, я хочу создать встречу, пригласить коллег и назначить ее на конкретный час, чтобы согласовать совместное время.

Как сотрудник, я хочу видеть список приглашений на встречи, чтобы подтвердить или отклонить их.

Как сотрудник, я хочу просматривать свое расписание (день/неделя/месяц), чтобы эффективно планировать свое время.

Как администратор, я хочу управлять учетными записями сотрудников (добавлять/редактировать/удалять), чтобы поддерживать актуальность системы.

Как пользователь, я хочу иметь удобный и интуитивно понятный интерфейс, чтобы быстро выполнять нужные действия.

Use Cases (Сценарии использования)

UC-1: Регистрация и авторизация сотрудника

Цель: Получение доступа к системе.

Участники: Сотрудник.

Предусловия: Нет.

Основной поток:

Пользователь вводит email, пароль, имя и другие обязательные данные.
Система проверяет уникальность email.
Система создает учетную запись и сохраняет ее в БД.
Система авторизует пользователя и перенаправляет на главный экран.

Альтернативный поток A (Неверный формат данных):
Система показывает сообщение об ошибке в соответствующем поле.
Пользователь исправляет данные.


UC-2: Редактирование личного профиля
Цель: Обновление информации о себе.

Участники: Сотрудник.

Предусловия: Пользователь авторизован.

Основной поток:
Пользователь переходит в раздел «Профиль».
Пользователь изменяет данные (имя, должность, аватар, контакты).
Система сохраняет изменения в БД.
Система показывает уведомление об успешном обновлении.

Альтернативный поток A (Данные не прошли валидацию):
Система показывает ошибку.
Пользователь исправляет данные.


UC-3: Создание встречи
Цель: Организовать встречу с коллегами.

Участники: Сотрудник.

Предусловия: Пользователь авторизован.

Основной поток:
Пользователь нажимает «Создать встречу».
Пользователь выбирает дату, час начала (например, 9:00), продолжительность (в часах), название, описание.
Пользователь выбирает из списка коллег для приглашения.
Система проверяет, что выбранный временной слот свободен у организатора.
Система проверяет свободность слотов у приглашенных пользователей и отображает предупреждение, если у кого-то есть конфликт.
Система сохраняет встречу в БД.
Система создает приглашения для участников со статусом "Ожидает ответа".
Система сохраняет встречу в БД и создает приглашения для участников.
Участники получают уведомления о новой встрече.
Система показывает сообщение об успешном создании встречи.

Альтернативный поток A (Слот занят):
Система показывает сообщение: «У вас уже есть встреча на это время».
Пользователь выбирает другой временной слот.
Возврат к шагу 4 основного потока.

Альтернативный поток B (Конфликт у приглашенных):
Система показывает предупреждение: «У следующих пользователей есть встречи в это время: [список имен]».
Пользователь может:
Изменить время встречи
Убрать пользователей с конфликтами из списка приглашенных

В зависимости от выбора, продолжается основной поток.

UC-4: Ответ на приглашение на встречу
Цель: Подтвердить или отклонить участие во встрече.

Участники: Сотрудник (приглашенный).

Предусловия: Пользователь авторизован, есть входящие приглашения.

Основной поток:
Пользователь переходит во вкладку «Приглашения».
Пользователь просматривает список приглашений (название, время, организатор, продолжительность).
Пользователь нажимает «Принять» или «Отклонить» для выбранного приглашения.
Система проверяет, что на это время у пользователя нет других подтвержденных встреч.
Система обновляет статус приглашения в БД.
Система добавляет встречу в расписание пользователя.
Система уведомляет организатора о решении участника.
Система показывает подтверждение об успешном принятии приглашения.
Система уведомляет организатора о решении участника.

Альтернативный поток B (Конфликт времени при принятии):

Система обнаруживает, что на это время у пользователя уже есть другая подтвержденная встреча.
Система показывает сообщение: «У вас уже есть встреча на это время. Вы не можете принять это приглашение».
Пользователь может:
Отклонить приглашение
Перенести свою существующую встречу (если он ее организатор)
В зависимости от выбора, продолжается соответствующий поток.


UC-5: Просмотр расписания
Цель: Увидеть свои запланированные встречи.

Участники: Сотрудник.

Предусловия: Пользователь авторизован.

Основной поток:
Пользователь переходит на вкладку «Расписание».
Пользователь выбирает режим отображения: день, неделя, месяц.
Система запрашивает с сервера встречи для выбранного периода.
Система отображает встречи в виде наглядного календаря/списка.

Альтернативный поток: Нет.


UC-6: Управление учетными записями сотрудников
Цель: Администрирование пользовательских учетных записей в системе.

Участники: Администратор.

Предусловия: Пользователь авторизован с ролью администратора.

Основной поток (Добавление сотрудника):
Администратор переходит в раздел «Управление пользователями».
Администратор нажимает «Добавить сотрудника».
Система показывает форму с полями: email, имя, фамилия, должность, отдел.
Администратор заполняет обязательные поля.
Система создает учетную запись в БД.
Система показывает подтверждение об успешном добавлении.

Альтернативный поток A (Редактирование сотрудника):
Администратор выбирает сотрудника из списка.
Администратор нажимает «Редактировать».
Система показывает форму с текущими данными.
Администратор вносит изменения.
Система сохраняет изменения в БД.
Система показывает подтверждение об успешном обновлении.

Альтернативный поток B (Удаление сотрудника):

Администратор выбирает сотрудника.
Администратор нажимает «Удалить».
Система запрашивает подтверждение.
Система удаляет учетную запись.
Система отменяет все будущие встречи сотрудника и уведомляет участников.
Система показывает подтверждение об успешной деактивации.


UC-7: Обеспечение удобного пользовательского интерфейса
Цель: Предоставить интуитивно понятный интерфейс для выполнения задач.

Участники: Любой пользователь системы.

Предусловия: Пользователь имеет доступ к системе.

Основной поток:
Пользователь открывает приложение.
Система отображает понятную навигацию с четкими иконками и подписями.
Пользователь интуитивно находит нужный раздел (расписание, встречи, профиль).
Пользователь выполняет желаемое действие через понятный интерфейс.
Система предоставляет визуальную обратную связь о результате действия.

Альтернативный поток: Нет.

# Техническое задание на разработку программного продукта для планирования встреч

## Команда: while (Win)

## 1. Общие описание
Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании. Система состоит из клиентского мобильного приложения и серверной части.

## 2. Клиентская часть (Android-приложение)
Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java** с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий функционал:

*   **Регистрация и авторизация** сотрудника.
*   **Настройка личного профиля**.
*   **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны иметь возможность дать бинарный ответ (**принял** / **не принял**).
*   **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности посещения.
*   **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## 3. Серверная часть
Сервер представляет собой **микросервис на Spring Boot**, работающий с СУБД **PostgreSQL** или **H2**.

Серверное приложение должно:
*   Предоставлять API, необходимый для полноценной работы мобильного приложения.
*   Осуществлять все основные операции с данными в базе через **Spring Data JPA**.
*   Использовать **Liquibase** для создания схемы базы данных и ее предзаполнения.

# User Stories
1. Как сотрудник компании, я хочу зарегистрироваться в системе, чтобы планировать встречи
2. Как зарегистрированный пользователь, я хочу войти в систему, чтобы пользоваться функционалом приложения
3. Как пользователь, я хочу редактировать свой профиль, чтобы другие видели актуальную информацию обо мне
4. Как пользователь, я хочу создать встречу, чтобы встретиться с коллегами
5. Как создатель встречи, я хочу пригласить других пользователей, чтобы они могли ответить на предложение
6. Как пользователь, я хочу просматривать список приглашений, чтобы отвечать на них
7. Как приглашенный пользователь, я хочу ответить на предложение, чтобы организатор узнал о моем решении
8. Как участник встреч, я хочу видеть свое расписание встреч, чтобы планировать время

# Use Cases
## 1. Регистрация пользователя

**Цель:** Регистрация пользователя для последующего входа  
**Акторы:** Сотрудник  
**Предусловие:** Сотрудник не зарегистрирован

### Основной поток:
1. Пользователь вводит почту, пароль и подтверждение пароля
2. Приложение отправляет данные на сервер
3. Сервер проверяет:
   - уникальность почты
   - совпадение пароля и подтверждения пароля
   - соответствие пароля требованиям
4. Сервер возвращает успешный ответ
5. Приложение переходит на экран авторизации

### Альтернативный поток:
- Пользователь с такой почтой уже существует / пароли не совпадают / пароль слишком слабый
- Сервер возвращает ошибку
- Приложение отображает сообщение об ошибке

## 2. Авторизация пользователя

**Цель:** Вход пользователя в систему  
**Акторы:** Сотрудник  
**Предусловие:** Сотрудник зарегистрирован

### Основной поток:
1. Пользователь вводит почту и пароль
2. Приложение отправляет данные на сервер
3. Сервер проверяет, существует ли такой пользователь
4. Сервер возвращает токен авторизации
5. Приложение сохраняет токен
6. Пользователь переходит на главный экран

### Альтернативный поток:
- Введена неверная почта или пароль
- Сервер возвращает ошибку авторизации
- Приложение отображает сообщение об ошибке

## 3. Редактирование профиля пользователя

**Цель:** Обновление личных данных пользователя  
**Акторы:** Сотрудник  
**Предусловие:** Пользователь авторизован

### Основной поток:
1. Пользователь открывает экран профиля
2. Пользователь изменяет данные
3. Пользователь нажимает кнопку сохранения
4. Приложение отправляет данные на сервер
5. Сервер обновляет данные пользователя в базе
6. Сервер возвращает успешный ответ
7. Приложение обновляет интерфейс

### Альтернативный поток:
- Данные не прошли валидацию
- Сервер возвращает ошибку
- Приложение отображает сообщение об ошибке

## 4. Создание встречи

**Цель:** Создание новой встречи  
**Акторы:** Сотрудник  
**Предусловие:** Пользователь авторизован

### Основной поток:
1. Пользователь вводит название и описание встречи
2. Пользователь выбирает дату и время начала и окончания встречи
3. Пользователь выбирает сотрудников для приглашения
4. Приложение отправляет данные встречи на сервер
5. Сервер выполняет проверки
6. Сервер сохраняет встречу в базе данных
7. Сервер создает приглашения для выбранных сотрудников
8. Сервер возвращает успешный ответ

### Альтернативный поток:
- Время указано не по целым часам / конец встречи раньше начала / встреча пересекается с другой
- Сервер возвращает ошибку
- Приложение отображает сообщение об ошибке

## 5. Просмотр приглашений на встречи

**Цель:** Просмотр списка приглашений пользователя  
**Акторы:** Сотрудник  
**Предусловие:** Пользователь авторизован

### Основной поток:
1. Пользователь открывает раздел с приглашениями
2. Приложение отправляет запрос на сервер
3. Сервер возвращает список активных приглашений
4. Приложение отображает список  

## 6. Ответ на приглашение

**Цель:** Принятие или отклонение приглашения  
**Акторы:** Сотрудник  
**Предусловие:** Пользователь авторизован, приглашение существует

### Основной поток:
1. Пользователь принимает или отклоняет приглашение
2. Приложение отправляет ответ на сервер
3. Сервер сохраняет статус приглашения
4. Сервер возвращает успешный ответ
5. Приложение обновляет статус

### Альтернативный поток:
- Пользователь не приглашен / приглашение уже было обработано
- Сервер возвращает ошибку
- Приложение отображает сообщение об ошибке

## 7. Просмотр расписания встреч

**Цель:** Просмотр личного расписания встреч  
**Акторы:** Сотрудник  
**Предусловие:** Пользователь авторизован

### Основной поток:
1. Пользователь выбирает режим просмотра (день / неделя / месяц)
2. Приложение отправляет запрос на сервер
3. Сервер возвращает расписание пользователя
4. Приложение отображает расписание

## 8. Выход пользователя из системы

**Цель:** Завершение пользовательской сессии  
**Акторы:** Сотрудник  
**Предусловие:** Пользователь авторизован

### Основной поток:
1. Пользователь нажимает кнопку выхода
2. Приложение удаляет сохранённый токен
3. Пользователь перенаправляется на экран авторизации

# Задачи для Backend

## 1. Регистрация пользователя

- Реализовать REST API регистрации
- Выполнять валидацию email и пароля
- Хешировать пароль
- Сохранять пользователя в БД
- Обрабатывать и возвращать ошибки

## 2. Авторизация пользователя

- Реализовать REST API авторизации
- Проверять учетные данные
- Генерировать JWT-токен
- Возвращать токен клиенту
- Обрабатывать ошибки авторизации

## 3. Управление профилем пользователя

- Реализовать API получения профиля
- Реализовать API обновления профиля
- Валидировать данные

## 4. Создание встречи

- Реализовать API создания встречи
- Проверять корректность указанного времени
- Проверять пересечения встреч
- Сохранять встречу

## 5. Работа с приглашениями

- Реализовать API создания приглашений (для оргазизаторов)
- Реализовать API получения приглашений
- Реализовать API ответа на приглашение (для приглашенных)
- Обновлять статус приглашения

## 6. Получение расписания  

- Реализовать API получения расписания
- Поддерживать выбор периода
- Формировать расписание из:
  - встреч, где пользователь организатор
  - встреч, где приглашение принято

## 7. Выход пользователя

- Реализовать механизм выхода
- Инвалидировать токен

## 8. Общее

- Настроить Spring Boot приложение
- Настроить БД и JPA
- Настроить Liquibase
- Реализовать обработку ошибок
- Настроить логирование

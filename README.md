# Техническое задание на разработку программного продукта для планирования встреч

## 1. Общие описание
Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании. Система состоит из клиентского мобильного приложения и серверной части.

## 2. Клиентская часть (Android-приложение)
Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java** с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий функционал:

*   **Регистрация и авторизация** сотрудника.
*   **Настройка личного профиля**.
*   **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны иметь возможность дать бинарный ответ (**принял** / **не принял**).
*   **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности посещения.
*   **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## 3. Серверная часть
Сервер представляет собой **микросервис на Spring Boot**, работающий с СУБД **PostgreSQL** или **H2**.

Серверное приложение должно:
*   Предоставлять API, необходимый для полноценной работы мобильного приложения.
*   Осуществлять все основные операции с данными в базе через **Spring Data JPA**.
*   Использовать **Liquibase** для создания схемы базы данных и ее предзаполнения.

# User stories: 
- Я, как пользователь, хочу зарегистрироваться, чтобы создать профиль 
- Я, как пользователь, хочу авторизоваться, чтобы получить доступ к приложению
- Я, как пользователь, хочу иметь возможность настроить профиль, чтобы другие пользователи могли узнать, всю необходимую информацию обо мне
- Я, как пользователь, хочу создавать встречи на конкретные дату и время и иметь возможность приглашать на них сотрудников из общего списка с возможностью поиска, чтобы удобно планировать встречи
- Я, как организатор встречи, при выборе сотрудников на приглашение хочу иметь возможность просмотреть информацию о сотруднике
- Я, как пользователь, хочу в одном месте видеть все активные приглашения на встречи с возможностью удобно давать бинарный ответ, потому что приглашений может быть много и хочется разобраться с каждым побыстрее
- Я, как пользователь, хочу видеть встречи, на которые я записался, в удобном виде, с возможностью посмотреть встречи на какой-либо день, неделю, месяц, чтобы легче планировать встречи 
- Я, как пользователь, при рассмотрении приглашения или просмотре расписания хочу иметь возможность получить подробную информацию о встрече
- Я, как пользователь, хочу видеть встречи, на которые я записался, в календаре, чтобы удобно управлять своим временем

# Use cases: 
Цель: регистрация пользователя

Участники: пользователь

Предусловия: нет

Основной поток: пользователь вводит свои ФИО, должность в компании, логин(рабочий email) и пароль(обязательная часть) и некоторые другие данные. Email проверяется на валидность, а пароль - на надежность. Данные отправляются в базу данных. Приложение переходит на главный экран.

Альтернативный поток: данные, введенные пользователем, неверны или ненадежны, либо пользователь с таким логином уже зарегистрирован. Приложение выводит предупреждающее сообщение и ожидает правильных данных.
***
Цель: авторизация пользователя

Участники: пользователь

Предусловия: нет

Основной поток: пользователь вводит свои логин и пароль в поля ввода. Данные сравниваются с данными из базы данных. При совпадении пользователю выдается доступ к его учетной записи.

Альтернативный поток: при несовпадении данных выводится сообщение "Неверный email или пароль".
***
Цель: редактирование профиля пользователя

Участники: пользователь

Предусловия: пользователь авторизован

Основной поток: пользователь заходит на страницу своего профиля. Он может редактировать дополнительную информацию, изменять пароль. При нажатии на кнопку "Готово" отправляется запрос на обновление данных в БД.

Альтернативный поток: при вводе невалидных данных выводится предупреждение, ожидаются правильные данные.
***
Цель: создание встречи

Участники: пользователь

Предусловия: пользователь авторизован

Основной поток: пользователь нажимает на кнопку "Создать новую встречу". Создание встречи состоит из ввода названия встречи, выбора даты, времени и списка сотрудников, извлекаемого из БД. Предусмотрены возможность поиска по ФИО / должности и открытие карточки о пользователе. Справа от каждого сотрудника в общем списке - toggle с галочкой для выбора сотрудника. После пользователь нажимает кнопку "Готово", создается запрос на добавление информации о созданной встрече, а также происходит рассылка приглашений.

Альтернативный поток: ошибка если не выбрано название / время / дата, либо время начала позже времени окончания
***
Цель: увидеть список приглашений и дать ответ на них

Участники: пользователь

Предусловия: пользователь авторизован

Основной поток: при открытии вкладки "Приглашения" отправляется запрос в БД, оттуда приходят данные о встречах, на которые приглашен данный пользователь, в виде списка. Каждое приглашение можно принять или отклонить, а также посмотреть подробную информацию о встрече. В случае принятия приглашения встреча считается запланированной для пользователя. После предоставления ответа приглашение пропадает из списка приглашений. 

Альтернативный поток: ошибка сервера
***
Цель: посмотреть расписание

Участники: пользователь

Предусловия: пользователь авторизован

Основной поток: пользователь открывает вкладку "Расписание". Из БД вытаскивается список запланированных встреч пользователя. Эти встречи отображаются по выбранному дню / неделе / месяцу. 

Альтернативный поток: ошибка сервера

# Backend Tasks:
- Развернуть базу данных с таблицами для хранения данных о зарегистрированных пользователях, данных о сотрудниках, данных о существующих встречах, данных об активных приглашениях для каждого пользователя и о запланированных встречах для каждого пользователя.
- Реализовать API для регистрации и авторизации:
	- Добавление данных о новом пользователе.
	- Проверка уникальности данных при авторизации.
	- Выдача токена авторизации.
- Реализовать API для получения данных о пользователе и их редактирования:
- Реализовать API для создания встречи.
- Реализовать API для создания приглашений и получения данных о них.
- Реализовать API для создания запланированной встречи и получения данных о запланированных встречах.
- Написать интеграционные и API-тесты для проверки всех функций приложения.
